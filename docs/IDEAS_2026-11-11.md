# Feature ideas (2026-11-11)

Ideas only: none of these is designed, scoped or scheduled. Anything picked up
still needs its own spec and plan, as `docs/ROADMAP.md` describes.

## Sort only what is loose in root

From a friend's suggestion: one button that protects every folder and leaves
mods sitting in the root unprotected. In effect the root becomes an inbox:
everything already filed stays put, and only loose mods get sorted.

Open questions for a spec:

- Is it a one-off action that writes protect rules, or a Sort mode ("only
  root mods") that leaves the saved rules alone? The mode is easier to undo.
- How does it interact with existing exclude rules and sort-inside folders?

## Ideas that build on it

- **New-mod prompt.** When mods are installed, show "3 unsorted mods, sort
  them?" and sort only those. Needs a check of which Penumbra IPC events
  report a newly added mod.
- **Chat command.** Something like `/porg sortnew` for people who don't want
  to open the window.

## Other ideas

- **Unused mods report.** List mods not enabled in any collection, with size
  on disk, and offer to move them to an "Unused" folder. Needs a check of
  what the IPC exposes per collection.
- **Duplicate and old-version finder.** The same mod installed twice or in
  two versions, showing which one is actually in use.
- **Tag surfacing.** The roadmap's "Auto mod tagging" section already found
  that reading `ModTags` and `LocalTags` needs no new IPC. Show them, filter
  by them, and allow "tag -> folder" rules. Read-only; writing tags stays
  parked.
- **Custom rules.** User-defined "if name or creator contains X, put it in
  Y", applied before the automatic sort.

## Before any of these

The first-run tutorial rewrite already on the roadmap's to-do list probably
matters more for new users than any new feature.
